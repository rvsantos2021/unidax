# UNIDAX V4.3 — SEO, performance e aquisição B2B

## Entregas desta versão

- Landing pages individuais e estáticas para os três serviços prioritários de IA:
  - `/ia/desenvolvimento-de-sistemas-de-ia`
  - `/ia/consultoria-estrategica-em-ia`
  - `/ia/agentes-de-ia-para-empresas`
- Landing pages individuais para seis linhas de serviços empresariais:
  - `/servicos/erp-dynamics`
  - `/servicos/desenvolvimento-de-sistemas`
  - `/servicos/data-analytics`
  - `/servicos/power-platform`
  - `/servicos/outsourcing-squads`
  - `/servicos/suporte-sustentacao`
- Metadata por página, canonical, Open Graph e Twitter Cards.
- `Service`/`ProfessionalService` JSON-LD e `BreadcrumbList` nas páginas de serviço.
- FAQ visível e FAQPage JSON-LD com respostas iguais às exibidas na interface.
- Sitemap estendido com as novas páginas.
- CTAs contextuais que preenchem o interesse na URL do contato.
- Cards de IA e serviços levam às páginas detalhadas correspondentes.
- FAQ com `details/summary`, navegável por teclado e sem JavaScript adicional.

## Princípios de conteúdo e SEO

- Conteúdo escrito para pessoas e intenção de busca; não há promessa de posições no Google.
- Não publicar depoimentos, certificações, métricas de resultado ou alegações de parceria sem comprovação/autorização.
- Dados estruturados descrevem apenas o conteúdo presente na página.
- FAQ rich results não são garantidos pelos mecanismos de busca; o schema ajuda a explicitar a estrutura, não garante exibição especial.
- Revisar títulos, conteúdo, links internos e palavras-chave com dados reais do Search Console antes da publicação.

## Checklist de validação local

Requer Node.js compatível com Next.js 15 e acesso ao registry npm:

```bash
npm ci
npm run typecheck
npm run lint
npm run build
npm run start
```

Depois, verificar manualmente:

- todas as rotas listadas neste documento;
- canonical e metadata no HTML renderizado;
- `/sitemap.xml` e `/robots.txt`;
- schema no Rich Results Test / Schema Markup Validator;
- formulário, e-mail, webhook de CRM e consentimento de analytics;
- teclado, foco, contraste e leitor de tela;
- Lighthouse mobile em homepage, landing page, artigo e contato.

## Performance: decisões e próximos passos

As páginas de serviço usam renderização no servidor e parâmetros estáticos. As FAQs usam HTML nativo e não adicionam dependência de JavaScript. Para a validação final, medir LCP, INP e CLS em ambiente publicado. O hero, fontes, scripts de terceiros e consentimento devem ser avaliados com dados reais; não se declara uma pontuação Lighthouse sem executar o teste.

## Antes de publicar

1. Confirmar o domínio canônico (`https://www.unidax.com.br` ou domínio sem `www`) e redirecionamentos 301.
2. Revisar os textos e a oferta comercial com os responsáveis da UNIDAX.
3. Configurar e testar e-mail, CRM, GA4 e política de cookies.
4. Validar os dados estruturados e indexação após deploy.
5. Cadastrar sitemap no Google Search Console e monitorar consultas, impressões, cliques e conversões.
