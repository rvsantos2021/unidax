# UNIDAX V4.4 — Validação técnica e preparação para lançamento

## Escopo desta versão

Esta etapa consolida a V4.3 como candidata a homologação. Não altera o posicionamento de marca e não publica automaticamente no domínio de produção.

### Controles incluídos
- Versão do pacote atualizada para `4.4.0`.
- Script estático `npm run check:routes` para conferir arquivos/rotas essenciais e detectar duplicação de slugs no catálogo SEO.
- Pipeline GitHub Actions já presente para `typecheck`, `lint` e `build`.
- Checklist operacional abaixo para homologação e lançamento.

## Execução local

Requisitos: Node.js 20 ou superior e acesso ao registry npm.

```bash
npm ci
npm run check:routes
npm run typecheck
npm run lint
npm run build
npm run start
```

Depois, validar manualmente em navegador as rotas, formulários e consentimento descritos abaixo.

## Checklist de homologação

### Build e rotas
- [ ] `npm ci` finaliza sem erros e o lockfile é versionado.
- [ ] `check:routes`, `typecheck`, `lint` e `build` passam.
- [ ] Home, IA, cada landing page de IA, Serviços, cada landing page empresarial, Cases, Insights, artigos, Empresa, Contato, Privacidade e Obrigado respondem corretamente.
- [ ] Slugs inexistentes retornam 404.
- [ ] Sitemap e robots usam o domínio canônico definitivo.
- [ ] Canonical, títulos e descrições são únicos e corretos em cada página.

### Formulário e integrações
- [ ] Validar campos no cliente e no servidor.
- [ ] Confirmar mensagens de sucesso e erro, honeypot e proteção contra abuso.
- [ ] Confirmar que `RESEND_API_KEY`, remetente verificado e destinatário estão configurados no ambiente de homologação.
- [ ] Confirmar webhook do CRM, autenticação, timeout, logs sem dados pessoais e política de retentativa.
- [ ] Confirmar que o lead não é apresentado como entregue ao comercial se os canais configurados falharem.
- [ ] Confirmar captura e sanitização de UTM, `gclid`, `fbclid`, landing page e referrer.

### Privacidade e segurança
- [ ] Revisar política de privacidade com responsável jurídico/privacidade da UNIDAX.
- [ ] Validar consentimento antes de carregar GA4 e funcionamento de recusa/revogação.
- [ ] Confirmar retenção, acesso e exclusão de leads no e-mail/CRM.
- [ ] Validar headers, CSP (se adotada sem quebrar recursos), limites de requisição e proteção anti-spam em infraestrutura real.
- [ ] Revisar variáveis de ambiente; nenhum segredo deve estar no repositório ou em `NEXT_PUBLIC_*`.

### SEO, acessibilidade e desempenho
- [ ] Executar Lighthouse em mobile e desktop em build de produção.
- [ ] Medir Core Web Vitals reais após publicação: LCP, INP e CLS.
- [ ] Testar teclado, foco, leitores de tela, zoom e contraste.
- [ ] Confirmar alt text, links internos, estados de carregamento e erros.
- [ ] Validar JSON-LD com ferramenta de teste; os dados devem corresponder ao conteúdo visível.
- [ ] Verificar OG image, favicon, compartilhamento e indexação no Search Console.

### Deploy e reversão
- [ ] Definir domínio canônico e DNS/SSL.
- [ ] Configurar variáveis em preview/staging e produção separadamente.
- [ ] Rodar smoke tests após deploy.
- [ ] Configurar monitoramento de erros, disponibilidade e envio de leads.
- [ ] Ter rollback para a versão anterior e plano de restauração.
- [ ] Publicar sitemap no Search Console e monitorar erros de rastreamento.

## Estado de validação desta entrega

O ambiente de execução usado para preparar este pacote não conseguiu concluir `npm install` dentro do limite de tempo. Portanto, **não há confirmação de que `typecheck`, `lint` ou `next build` passaram**. O script de rotas é um controle estático complementar e não substitui compilação nem teste de navegador. Trate esta entrega como candidata a homologação, não como publicação aprovada.

## Critério de pronto para produção

A publicação só deve ser aprovada depois de todos os checks críticos de build, formulário, privacidade, domínio e rollback estarem concluídos. Cases e métricas de clientes só devem ser publicados com conteúdo e autorização formal.
