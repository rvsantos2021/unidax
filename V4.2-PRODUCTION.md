# UNIDAX V4.2 — CMS, conteúdo comercial e conversão

## Objetivo

A V4.2 evolui o site de um catálogo institucional para uma plataforma editorial e comercial. A camada visual continua desacoplada do conteúdo e agora pode consumir um CMS headless, mantendo fallback local para desenvolvimento e continuidade.

## CMS

O adaptador `lib/cms.ts` usa Sanity via HTTP, sem acoplar o site ao SDK do fornecedor. Quando `SANITY_PROJECT_ID` e `SANITY_DATASET` estão configurados, o conteúdo publicado é lido do Sanity; sem essas variáveis, o site usa `lib/content.ts`.

### Conteúdos suportados
- Insights
- Cases

### Studio

A pasta `studio/` contém um Sanity Studio independente com schemas para `insight` e `caseStudy`. Instalação e deploy do Studio devem ocorrer separadamente do app Next.js.

## Conversão B2B

O formulário agora captura:
- UTM source / medium / campaign / content / term
- GCLID / FBCLID
- landing page
- referrer

O lead é enviado por e-mail via Resend e, se `CRM_WEBHOOK_URL` estiver configurado, também é encaminhado para o CRM/middleware comercial.

O webhook é best-effort: uma falha do CRM não invalida a entrega primária do lead por e-mail.

## Jornada pós-conversão

`/contato` → `POST /api/contact` → `/obrigado`

A página de obrigado não é indexada e registra o evento `generate_lead` no `dataLayer`.

## Analytics

O evento de conversão é disparado somente no navegador. O GA4 continua condicionado ao consentimento de analytics implementado na V4.1.

## Próxima evolução

Antes de produção definitiva:
1. Criar projeto/dataset do Sanity.
2. Publicar o Studio.
3. Cadastrar conteúdos aprovados pela UNIDAX.
4. Conectar o CRM via `CRM_WEBHOOK_URL`.
5. Configurar Resend e domínio remetente.
6. Validar consentimento, política de privacidade e retenção de leads com jurídico/DPO.
7. Executar `npm install`, `npm run typecheck`, `npm run lint` e `npm run build`.
