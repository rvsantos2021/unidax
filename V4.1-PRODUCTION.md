# UNIDAX V4.1 — Refinamento de produção

## Entregas
- Conteúdo editorial tipado e preparado para migração para CMS.
- Rotas individuais para Insights e Cases com metadata dinâmica.
- JSON-LD de Article nas páginas de Insights.
- Sitemap expandido para artigos e cases.
- Open Graph dinâmico com `next/og`.
- Favicon SVG e metadata social.
- Banner de consentimento para analytics opcional.
- GA4 carregado somente após consentimento, quando `NEXT_PUBLIC_GA_ID` estiver configurado.
- Headers HTTP de segurança básicos.
- Melhorias de foco, navegação por teclado, Escape no menu e regiões ARIA.
- CI com typecheck, lint e build.
- Política de conteúdo responsável: resultados de cases só entram após autorização.

## CMS
A camada `lib/content.ts` funciona como repositório editorial inicial. Para produção, ela pode ser substituída por Sanity, Storyblok, Contentful ou outro CMS headless sem alterar os componentes de apresentação. O contrato recomendado é manter `slug`, `title`, `excerpt`, `publishedAt`, `status`, taxonomia e conteúdo estruturado.

## Analytics
Configure `NEXT_PUBLIC_GA_ID` somente se a UNIDAX decidir usar GA4. O script não é carregado antes do consentimento. A política de privacidade definitiva deve ser revisada juridicamente e refletir os fornecedores efetivamente utilizados.

## Antes do go-live
1. Executar `npm ci`, `npm run typecheck`, `npm run lint` e `npm run build`.
2. Configurar domínio e `NEXT_PUBLIC_SITE_URL`.
3. Configurar Resend/CRM para o formulário.
4. Substituir o hero provisório por ativo visual definitivo/licenciado.
5. Validar conteúdo de cases com autorização dos clientes.
6. Revisar política de privacidade, cookies e bases legais com jurídico.
7. Configurar Search Console/Bing Webmaster e enviar sitemap.
8. Auditar Lighthouse, Core Web Vitals, acessibilidade e links quebrados.
